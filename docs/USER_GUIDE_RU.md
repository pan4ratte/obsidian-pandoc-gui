Это руководство можно открыть из палитры команд — «Pandoc GUI: Открыть руководство пользователя» или из панели управления в настройках плагина.

## 1. Шаблоны экспорта

Шаблоны хранят настройки для экспорта в конкретный формат, а редактор шаблонов позволяет настроить в графическом интерфейсе команды, которые будут отправлены в Pandoc во время экспорта: каждая команда Pandoc доступна в интерфейсе, поэтому у вас нет необходимости пользоваться командной строкой. Таблица с сохранёнными шаблонами в настройках плагина позволяет редактировать их, создавать новые или создавать копии существующих шаблонов.

После выбора формата экспорта редактор отображает все доступные для этого типа документов настройки Pandoc, а также встроенные в плагин дополнительные опции, улучшающие экспорт.

### 1.1. Раздел «Итоговая команда»

В разделе «Итоговая команда» показана команда, которую получит Pandoc; для удобства чтения каждому параметру выделена собственная строка. Переменные `${...}` в ней не подставлены: их значения известны только при экспорте (см. раздел 2). Кнопка копирования копирует команду целиком.

В поле «Дополнительные команды» можно дописать параметры Pandoc, для которых в редакторе нет опции, так как они редко используются — например, `--defaults=my.yaml`. Обратите внимание, что переменную шаблона вывода (`-V`), для которой нет своей опции, удобнее указать в поле «Другие переменные» в группе «Оформление документа»: по одному `ключ=значение` в строке, например `fontfamily=libertinus`.

### 1.2. Раздел «Метаданные документа»

В группе «Метаданные документа» можно заполнить заголовок, подзаголовок, автора, дату, аннотацию и другие поля документа, которые будут применяться ко всем заметкам, экспортируемым этим шаблоном.

* Если в свойствах заметки имеются метаданные (`title`, `author`, `date` и другие), они получают приоритет перед настройками шаблона.
* Значения читаются как Markdown, а `${...}` в них подставляется при экспорте: например, `${today.long}` в поле «Дата» даёт сегодняшнюю дату.
* Авторы и ключевые слова добавляются по одному: сначала введите значение, а затем нажмите Enter, чтобы элемент добавился в список.

## 2. Переменные `${...}`

Переменные подставляются при экспорте во всё, что пишет шаблон: в команду, в «Дополнительные команды» и в поля «Метаданных документа».

### 2.1. Переменные

В примерах заметка `/Users/aaa/Documents/readme.md` экспортируется в `/Users/aaa/Documents/test.pdf`:

| Переменная | Значение |
| ---------- | -------- |
| `${outputPath}` | Полный путь экспортированного файла: `/Users/aaa/Documents/test.pdf`. |
| `${outputDir}` | Папка экспортированного файла: `/Users/aaa/Documents`. |
| `${outputFileName}` | Имя экспортированного файла без расширения: `test`. |
| `${outputFileFullName}` | Имя экспортированного файла с расширением: `test.pdf`. |
| `${currentPath}` | Полный путь заметки: `/Users/aaa/Documents/readme.md`. |
| `${currentDir}` | Папка заметки: `/Users/aaa/Documents`. |
| `${currentFileName}` | Имя заметки без расширения: `readme`. |
| `${currentFileFullName}` | Имя заметки с расширением: `readme.md`. |
| `${vaultDir}` | Папка хранилища. |
| `${attachmentFolderPath}` | Папка вложений из настроек Obsidian. |
| `${pluginDir}` | Папка плагина: его ресурсы и расширения Pandoc WASM. |
| `${luaDir}` | Папка `lua/` плагина с установленными lua-фильтрами. |
| `${embedDirs}` | Папки файлов, вложенных в заметку, — для `--resource-path`. |
| `${fromFormat}` | Формат, в котором Pandoc читает заметку: `markdown+wikilinks_title_after_pipe`, а в хранилище с Markdown-ссылками — `markdown`. |
| `${today.long}`, `${today.medium}`, `${today.short}`, `${today.iso}` | Сегодняшняя дата на языке Obsidian: длинная, средняя и короткая запись, а также `2026-10-02`. |
| `${metadata.ключ}` | Свойство заметки: `keyword: value` в свойствах доступно как `${metadata.keyword}`. |
| `${metadataFile}` | Файл с метаданными документа из шаблона. Его подставляет сам плагин. |

### 2.2. Выражения

Кроме имени переменной, внутри `${...}` можно написать простое выражение — например, чтобы параметр попадал в команду, только когда он нужен:

| Запись | Что делает |
| ------ | ---------- |
| `${metadata.keyword}`, `${metadata["ключ"]}` | Обращение к полю. |
| `` ${ x ? `--opt="${x}"` : `` } `` | Условие. В ветках работают вложенные шаблонные строки. |
| `${x ?? "по умолчанию"}`, `${x \|\| "запасное"}`, `${x && "…"}`, `${!x}` | Значение по умолчанию и логические операции. |
| `${fmt === "pdf" ? "…" : "…"}` | Сравнение: `x === y`, `x !== y`, `x == y`, `x != y`. |

Функции вызывать нельзя: вместо `${outputFileName.toUpperCase()}` напишите `${outputFileName}`. Имя, которого нет среди переменных, не подставляется: `${user}` так и попадёт в команду.

### 2.3. Свои команды экспорта

Чтобы выполнить команду Pandoc, которую не покрывают опции редактора, или вообще запустить другую программу, выберите `Custom` в списке форматов рядом с названием шаблона. В поле «Команда» напишите команду с переменными, а в поле «Расширения целевых файлов» — расширение файла, который будет создан. Опция «Показывать вывод команды» покажет, что напечатала программа. Pandoc WASM такие шаблоны выполнять не умеет.

## 3. Синтаксис Obsidian

Опции группы «Чтение заметки» в «Расширенных настройках» отвечают за обработку синтаксиса Obsidian, которого нет у Pandoc по умолчанию.

### 3.1. Вложенные заметки

Если опция «Вставлять содержимое вложенных заметок» включена, то ссылка `![[заметка]]` заменяется текстом заметки, а `![[заметка#заголовок]]` — указанным разделом. Вложения внутри вложенных заметок тоже раскрываются. Опция «Подстраивать заголовки вложенных заметок» сдвигает их заголовки на уровень ниже того заголовка, под которым стоит вложение. В шаблонах Markdown опция выключена, и вложения остаются ссылками.

### 3.2. Другие опции

* «Вставлять сегодняшнюю дату вместо $today при экспорте» — каждое `$today` в заметке и её свойствах становится сегодняшней датой в выбранном формате.
* «Печатать свойство keywords» — ключевые слова из свойств заметки/шаблона печатаются в тексте документа с подписью из поля «Подпись ключевых слов».
* Плагин поддерживает интеграцию Excalidraw: рисунки Excalidraw экспортируются в документ как изображения. Для PDF и LaTeX опция «Формат рисунков Excalidraw» позволяет выбрать PNG или SVG (для SVG нужны пакет svg и Inkscape), а «Сохранять положение изображений» не даёт LaTeX переносить изображения с подписью в другое место.
* «Расширения» (рядом с «Lua-фильтрами») обрабатывают синтаксис, который Pandoc не читает по умолчанию: выноски, выделения, коды эмодзи, голые URL, одиночные переносы строк и другое.

### 3.3. Интеграция запросов Dataview

Важно: скрипты DataviewJS по умолчанию отключены в самом Dataview. Чтобы они экспортировались, включите в его настройках «Enable JavaScript queries». Плагин ждёт результат скрипта не дольше 10 секунд. Если скрипт не успевает, в документ попадает то, что он успел вывести, и об этом сообщается в окне предупреждений. Там же указываются запросы, которые не удалось выполнить.

Запросы Dataview попадают в документ так же, как они выглядят в режиме чтения:

* **Блоки `dataview`** — таблицы, списки и задачи, которые возвращает запрос.
* **Блоки `dataviewjs`** — то, что выводит скрипт: `dv.table`, `dv.list`, `dv.paragraph` и так далее.
* **Встроенные запросы** (инлайн-код, начинающийся со знака «=», например «= this.file.name») — их значение.

Запрос выполняется в той заметке, в которой он написан, поэтому `this.file` во вложенной заметке указывает на неё. Ссылки в результатах обрабатываются как обычные вики-ссылки: например, фильтр `strip-wikilinks.lua` удалит и их. Учитываются и настройки самого Dataview: ключевое слово блоков DataviewJS, префикс встроенных запросов и их отключение. Если опция «Вставлять содержимое вложенных заметок» выключена, выполняются только запросы самой заметки.

В виде кода остаются встроенные запросы DataviewJS (инлайн-код, начинающийся с «$=») и запросы `CALENDAR`: календарь нельзя представить ни таблицей, ни списком.

## 4. Документы Word

### 4.1. Референсные документы

Во время экспорта стили для оформления документов Word, OpenOffice или PowerPoint берутся из референсного документа, указанного в поле «Референсный документ». Кнопка «Сгенерировать референсный документ» позволяет создавать такие документы, используя инструментарий Pandoc. Документ будет создан в папке экспорта и будет указан в шаблоне.

### 4.2. Правка стилей

Группа «Правка стилей» исправляет то, как Pandoc назначает стили в Word и OpenOffice:

* «Применять стиль иллюстраций к изображениям» — изображение без подписи получает стиль иллюстрации.
* «Оформлять текст в ячейках таблиц» — ячейки получают указанный стиль вместо «Compact», а ячейки заголовка — свой.
* «Использовать стили списков Word» (только Word) — маркированные списки получают стиль List Bullet, а нумерованные — List Number. «Упрощать нумерованные списки» решает, начинается ли каждый список с 1.

Стиль с указанным названием должен быть в референсном документе.

### 4.3. Присоединение документов

При экспорте в Word к документу можно присоединить другие документы Word: например, титульный лист в начале и приложения в конце. Они переносятся целиком, вместе с полями страницы, колонтитулами, изображениями, списками, сносками и примечаниями, и выглядят так же, как в Word.

Документы задаются в редакторе шаблона в группе «Присоединение документов»: нажмите «+» в строке «Документ в начале» или «Документ в конце» и выберите один или несколько документов. Документы присоединяются в том же порядке, что и в списке, и их можно менять местами. Документ из хранилища запоминается по пути внутри хранилища, поэтому шаблон работает на всех устройствах, если вы пользуетесь синхронизацией.

Заметка может иметь свои документы в свойствах `docx-before` и `docx-after`: ссылкой на файл в хранилище, путём или списком из нескольких документов. Свойства заметки имеют приоритет перед документами, указанными в шаблоне, а пустое свойство отключает их для этой заметки. Пример указания документов в свойствах:

```yaml
docx-before: "[[Титульный лист.docx]]"
docx-after:
  - "[[Приложение А.docx]]"
  - "[[Приложение Б.docx]]"
```

Обратите внимание, что документы для присоединения также можно выбрать и в окне экспорта. Присоединение работает и с Pandoc WASM, в том числе на мобильных устройствах.

#### Стили присоединённых документов

* **Сохранить исходные стили** — документ сохраняет свой изначальный вид. Стили, которые есть в экспортированной заметке, будут переименованы с именем документа в скобках, например «Normal (Титульный лист)».
* **Использовать стили из шаблона** — если документ имеет стили с теми же названиями, что и в референсном документе, то будут использованы стили референсного документа, и присоединяемый файл будет переоформлен. При этом прямое форматирование (шрифт или выравнивание, заданные вручную) сохраняется.

#### Разделы и колонтитулы

Каждый присоединённый документ становится отдельным разделом со своими полями, размером страницы и колонтитулами и начинается с новой страницы, если в нём не задано иное. Колонтитулы одного документа не переходят на страницы следующего, а нумерация сносок в каждом документе начинается заново. Нумерация страниц продолжается через весь документ, так что титульный лист считается первой страницей.

Примечание: настройки, которые в Word задаются для всего документа, а не для раздела, — например, разные колонтитулы для чётных и нечётных страниц — берутся из экспортированной заметки. Встроенные в документ шрифты и макросы не переносятся. Документы в формате «Strict Open XML» не поддерживаются: пересохраните их в Word как обычный документ Word.

## 5. Lua-фильтры

Lua-фильтр — небольшой скрипт, который Pandoc применяет к документу при экспорте. Фильтры устанавливаются в магазине, который можно открыть из настроек плагина. Там фильтр можно найти по задаче, прочитать его требования и readme, установить, обновить и удалить. Также вы можете добавить свой собственный фильтр, выбрав в магазине опцию «Добавить свой lua-фильтр»: вставьте код или выберите файл.

Установленный фильтр подключается индивидуально к каждому шаблону в опции «Lua-фильтры» в редакторе. В списке отображаются только те фильтры, которые совместимы с форматом шаблона. Если фильтру нужна программа (например, mermaid-cli или lilypond), она должна быть доступна Pandoc — см. раздел 7.

## 6. Экспорт и импорт

### 6.1. Окно экспорта

Команда «Экспортировать заметку» открывает окно экспорта, где выбираются шаблон, имя файла и папка. Для форматов с оглавлением здесь можно изменить его глубину, а для Word — присоединённые документы: оба изменения применяются только к этому экспорту.

Команда «Экспортировать с предыдущими настройками» экспортирует заметку последним шаблоном в последнюю папку, без вызова окна экспорта. Папка запоминается для каждого устройства отдельно.

Если экспорт не удался, в окне ошибки будет подсказка и кнопка «Скопировать отчёт» — вставьте отчёт в сообщение об ошибке.

### 6.2. Импорт

Команда «Импортировать файл и конвертировать в заметку» превращает в заметку документ любого формата, который читает Pandoc: Word, OpenOffice, EPUB, HTML, LaTeX и другие.

## 7. Переменные среды

Установленный Pandoc запускается с переменными из настройки «Переменные среды» (кнопка «Изменить»). Они нужны, когда Pandoc или фильтр не находит программу — LaTeX, Typst, mermaid-cli, lilypond. Чаще всего это случается на macOS: Obsidian, запущенный не из терминала, не получает PATH оболочки. Папки Homebrew и TeX на macOS уже добавлены в PATH по умолчанию.

## 8. Pandoc WASM

Pandoc WASM — сборка Pandoc, которая работает прямо в Obsidian, в том числе на мобильных устройствах. Эта версия программы имеет некоторые архитектурные ограничения:

* **PDF — только через Typst.** Обычный шаблон «PDF» верстает через LaTeX, а запустить LaTeX Pandoc WASM не может. Такие шаблоны и слайды Beamer в окне экспорта не показываются: для PDF используйте шаблон «PDF (Typst)».
* **Шаблоны со своей командой не работают:** Pandoc WASM не может запускать программы, поэтому такие шаблоны тоже не показываются.
* **Только lua-фильтры.** Фильтры-программы, например на Python, не запустятся. Хорошая новость: все фильтры из магазина плагина — lua-фильтры.

### 8.1. PDF через Typst

Typst — программа вёрстки, которая работает в WASM: Pandoc пишет исходник Typst, а Typst верстает из него PDF. Typst устанавливается отдельно в настройках плагина: нажмите иконку расширений на карточке Pandoc WASM и выберите нужную опцию.

* Typst — другая программа со своим языком, поэтому шаблоны LaTeX (`--template=neurips.tex`), `-V geometry` и вставки сырого LaTeX (`\newpage`, `tikzpicture`) в PDF не попадут. Формулы, таблицы, изображения, оглавление и цитаты работают как обычно.
* Typst не видит шрифты системы. В него входят Libertinus, New Computer Modern и DejaVu — латиница, кириллица и математика. Чтобы добавить свои шрифты (например, для CJK или `-V mainfont`), укажите папку хранилища в строке «Шрифты» в расширениях.
* Без шрифта эмодзи эмодзи из заметки в PDF не попадут: он устанавливается там же.
* Typst пригодится и на компьютере: если установленный Pandoc не находит Typst в системе, PDF по шаблону «PDF (Typst)» соберёт эта сборка.

### 8.2. Расширения Pandoc WASM

Расширения снимают часть ограничений WASM и нужны прежде всего на телефоне. Они устанавливаются по иконке расширений на карточке Pandoc WASM и хранятся в папке плагина, поэтому в шаблоне на них можно сослаться через `${pluginDir}`:

* **Typst**, **шрифты** и **шрифт эмодзи** — вёрстка PDF, о ней выше.
* **Стили цитирования** — девять распространённых стилей CSL, в том числе APA, Chicago и ГОСТ Р 7.0.5-2008. Нужный файл укажите в поле «Стиль цитирования».
* **Шаблоны вёрстки Pandoc** — собственные шаблоны Pandoc для HTML, LaTeX, Typst и EPUB: скопируйте нужный, измените и укажите в поле «Шаблон вёрстки».
* **Референсные документы** — reference.docx, .odt и .pptx: настройте в них стили и укажите файл в поле «Референсный документ».
* **MathJax без сети** — чтобы формулы в HTML отрисовывались без интернета.

### 8.3. Что ещё учесть

* Pandoc WASM занимает около 56 МБ в папке плагина и синхронизируется вместе с хранилищем. Typst со шрифтами — ещё около 36 МБ, если вы его установили. Установка автоматическая, никаких ручных действий вам делать не нужно.
* Изображения по URL скачивает сам плагин перед конвертацией, до 64 изображений на экспорт: Pandoc WASM в сеть выходить не умеет. Обычные ссылки остаются ссылками.
* Нужен современный телефон: iOS 18.4 или новее либо Android с обновлённым WebView.

### 8.4. Неподдерживаемые параметры

Шаблон может содержать параметры, которых Pandoc WASM не поддерживает. При экспорте они пропускаются, а окно экспорта заранее об этом предупреждает. Предупреждение появится для:

* `--filter` — фильтров-программ;
* `--defaults` — файла настроек Pandoc;
* `--sandbox` и `--fail-if-warnings`;
* любого параметра, которого плагин не знает, включая устаревшие `--atx-headers` и `--epub-chapter-level`.

Эти параметры пропускаются без предупреждения — на результат они не влияют:

* `--pdf-engine`, `--pdf-engine-opt` — PDF всегда верстает Typst из плагина.
* `--request-header`, `--no-check-certificate` — в сеть ходит плагин, а не Pandoc.
* `--data-dir`, `--log`, `--verbose`, `--quiet`, `--trace`, `--dump-args` — нет ни системных папок, ни консоли, куда это можно было бы направить.
